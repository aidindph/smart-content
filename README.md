# موتور هوشمند تولید محتوا

ساخته‌شده و نگهداری‌شده توسط [آیدین قاسمی](https://github.com/aidindph) در پارس‌نست.

این پروژه یک نرم‌افزار چندکاربره برای تولید محتوای متنی و تصویری با کلیدهای شخصی کاربران است. مشتریان در داشبورد فضای کاری خود محتوا و اتصال‌ها را مدیریت می‌کنند و مدیر سامانه از پنلی جدا، کاربران، ثبت‌نام، ارائه‌دهندگان، مدل‌ها، قیمت‌ها و سهمیه‌ها را کنترل می‌کند. هدف، ارائهٔ یک جریان یکپارچه برای انتخاب مدل، تولید مقاله و تصویر، نگهداری تاریخچه، برآورد هزینه و استخراج فرصت‌های محتوایی از داده‌های سرچ کنسول است.

محدوده، ترتیب ساخت و معیار پایان هر مرحله در [نقشهٔ راه](docs/ROADMAP.md) ثبت شده است. هویت، مدیریت سامانه، مخزن امن کلیدها و مسیر کامل تولید و تاریخچه اکنون پیاده‌سازی شده‌اند.

## اصل توسعه

هر فاز باید خروجی قابل اجرا، مهاجرت‌های پایگاه داده، آزمون‌های متناسب و مستندات راه‌اندازی خودش را داشته باشد. تغییرات پس از عبور از کنترل‌های همان فاز در شاخهٔ اصلی مخزن ثبت می‌شوند.

## اجرای محلی

پیش‌نیازها Node.js 24، pnpm و Supabase CLI هستند.

```bash
pnpm install
supabase start
supabase db reset
pnpm dev
```

فایل `.env.example` را به `.env.local` کپی و مقادیر پروژهٔ محلی یا ابری Supabase را وارد کنید. برای اعمال کنترل ثبت‌نام در پروژهٔ ابری، تابع `public.before_user_created` را پس از اجرای مهاجرت‌ها در بخش Auth Hooks به‌عنوان هوک «پیش از ایجاد کاربر» انتخاب کنید.

ثبت‌نام عمومی به‌طور پیش‌فرض بسته است. مدیر سامانه از مسیر `/system-admin` می‌تواند وضعیت ثبت‌نام، حالت تعمیر و ارائه‌دهندگان هوش مصنوعی را تغییر دهد. داشبورد مشتری در مسیر `/dashboard` قرار دارد.

پردازش مقاله در جدول `generation_jobs` پایدار می‌ماند. مهاجرت پنجم یک زمان‌بند یک‌دقیقه‌ای در Supabase می‌سازد و نشانی و راز کارگر را از Vault می‌خواند؛ بنابراین اجرای صف به بازماندن صفحهٔ کاربر وابسته نیست. مقدار `WORKER_SECRET` در ورسل و Vault باید یکسان و محرمانه باشد.

برای فعال‌کردن اتصال سرچ کنسول، یک کارخواه وب OAuth در Google Cloud بسازید، نشانی `/api/google/callback` دامنهٔ تولید را به نشانی‌های بازگشت مجاز اضافه کنید و `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` را در محیط استقرار قرار دهید. برنامه فقط دامنهٔ `webmasters.readonly` را درخواست می‌کند.

برای ساخت نخستین مدیر، متغیرهای `BOOTSTRAP_ADMIN_EMAIL`، `BOOTSTRAP_ADMIN_PASSWORD` و در صورت نیاز `BOOTSTRAP_ADMIN_NAME` را فقط در محیط محلی تنظیم کنید و فرمان زیر را یک‌بار اجرا کنید. پس از موفقیت، این سه مقدار را حذف کنید.

```bash
pnpm admin:bootstrap
```
